System architecture

Each layer has one responsibility.

1

Candidate

Gives an answer in natural language or pseudocode.

2

NLP Extraction

Extracts structured information about what the candidate actually communicated.

3

Candidate NLP State

Maintains the evolving semantic representation of the candidate.

4

Reference Matching

Compares the current candidate state with the available reference solutions.

5

Evaluation

Evaluates reasoning quality across seven dimensions.

6

Classification and Gap Analysis

Identifies what is supported by evidence and what remains insufficiently assessed.

7

Adaptive Policy

Decides whether another turn is useful and what should be probed next.

8

Follow-up Generator

Generates a focused interviewer question from the current state and missing evidence.

Candidate Answer ↓ NLP Extraction ↓ Candidate NLP State ↓ Reference Matching ↓ reference_answer_id + reference_match_confidence ↓ Evaluation ↓ Classification + Gap Analysis ↓ Adaptive Policy ↓ Follow-up Question ↓ Next Candidate Answer
Reference matching is not evaluation

Reference Matching determines which existing approach resembles the candidate's current reasoning. Evaluation independently determines how good that reasoning is.

Confidence is not a score

reference_match_confidence is generated by the LLM matcher. It is not the candidate's correctness, evaluation score, or progress percentage. Python does not calculate it using a hardcoded formula.

Ownership

State lifecycle

Reference fields are initially empty and become populated after the candidate provides evidence.

Core mental model

The system continuously asks three different questions: What did the candidate communicate? Which reference matches that approach? How good is the reasoning, and what should we ask next?
